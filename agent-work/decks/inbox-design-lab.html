Layer 1 Answer where the request is

See the work, read the request, act on that card. Open Pi when the card cannot carry the interaction.

Shneiderman
Overview first, details on demand. D1 expands one selected card; D2 keeps neighbors scannable.
Weiser & Brown / Case
Calm technology keeps peripheral work quiet. D3 separates real requests from idle; D6 keeps feedback local; D7 avoids fleet-wide motion.
Endsley
Perceive, understand, predict. D2 names what and where; D3 states the request; D5 states when Pi will use a reply.
Bainbridge
Automation can leave the human with the hardest judgment. D3 keeps recommendation and evidence beside the request; D4 never substitutes a click for informed consent.
Norman
Visible signifiers and feedback prevent hidden modes. D4 labels answer focus; D5 labels delivery; D6 shows the result; D10 teaches the keys.
Horvitz
Mixed initiative treats attention as a cost. D1 keeps context in place; D4 stages answers without surprise sends; D10 leaves moving on to the user.
Tufte
Use ink for information. D2 drops repeated metadata before task text; D8 spends phone cells on identity, request and action; D9 removes duplicate controls.

Design lenses, not claims that these authors specified this UI. Sources: Shneiderman, The Eyes Have It, 1996; Weiser & Brown, Designing Calm Technology, 1995; Case, Calm Technology, 2015; Endsley, Toward a Theory of Situation Awareness, 1995; Bainbridge, Ironies of Automation, 1983; Norman, The Design of Everyday Things, revised 2013; Horvitz, Principles of Mixed-Initiative User Interfaces, 1999; Tufte, The Visual Display of Quantitative Information, 1983.

D1 One place to read and act

Approved A. Expand the selected card in place at every width. Shneiderman and Horvitz favor details without a second place to track.

Approved for inbox-003: place the existing selected-session workspace inside the shared card shell, not in a duplicate no-pin side column. i appends details/evidence there. Keep Status/Repo/board projections and synthetic-header safety. Pins and follow view remain opt-in. Fleet Enter and double-click mean Open in Pi; only focused answer/reply controls use Enter to submit.

D2 Task first, request below it

Approved A. Keep the task line on every card. Add the explicit request below it. Endsley supplies the reading order; width alone controls metadata removal.

Always retain the complete ticket subtitle, or the description only when there is no subtitle. Supported collapsed questions show the producer header in full, then the question fitted to the remaining cells with … . Expanded questions never truncate their content. Keep repo/branch beside [group] while they fit; drop branch, then repo before losing the task or request. The grid stays at 80+, the plain step name below 80. Only 160+ shows task counts and age. Apply the same width rules to every card state. Do not remove the task because of runtime, attention or height; scroll/window content instead. Show the key line only for the selected card.

D3 Requests are not runtime states

Approved A. Use the existing request glyph plus plain text. Bainbridge needs context; calm technology must not turn every waiting session into an alarm.

Display attention only on waiting/idle owners. Running/error/stopped stay runtime-led. A plain waiting or idle card can offer Reply, but claims no question. A ready handoff offers Reply / Open in Pi / Copy path, never invented options. Reading, selecting and Mark read are not approval. Child requests do not promote a parent. Evidence is a visible path or URL; Hub does not read the artifact.

D4 rpiv wording, Hub keys

Approved A. Answer inline with a numbered list, a Type something. row and question tabs. Norman makes focus visible; no extra review modal interrupts the answer.

Preserve producer option order and original indices. There is no generic recommended-option flag. Tab opens answer focus; Esc leaves without declining or cancelling; ←/→ switches questions outside text editing. t or the Type something. row enters literal custom text. In focused answers, Enter advances or sends; fleet Enter always opens Pi. At 100+ show all descriptions; below 100 show only the selected description. Show the selected option’s real preview text from the exact pending tool call in the live branch, using the same typed lookup source as Conversation. Guard the live conversation, interaction instance, branch and toolCallId; no transcript search, session-file reads or pane capture. Sanitize text and keep it out of heartbeat, registry and UI persistence. Match rpiv’s visual vocabulary without importing its private view code. Unsupported prompts and subagents offer Open in Pi.

D5 Reply with p, then send explicitly

Approved A. Keep the established p entry and put the editor on the card. Norman favors visible focus; Endsley requires an explicit delivery time.

Bind draft and send to {managedId, piSessionId, instanceId}, never the current row index. Esc keeps the exact target’s draft in dashboard memory; restart drops it. A new ready-handoff draft is prefilled Go ahead: <recommendation>; it remains editable, Ctrl+U clears it, and only Enter sends. Reopening an existing draft must not overwrite the user’s edits. Idle turning busy shows Rejected and requires an explicit Steer/Queue choice. Never silently change delivery or touch Pi’s editor. Idle Send expands templates; busy Steer/Queue stays literal. Subagents and unavailable bridges offer Open in Pi.

D6 Clear Accepted when work resumes

Approved A. Keep one receipt per exact live target. Norman closes the feedback loop without leaving a stale Accepted label over resumed work.

Submitting lasts until response or the existing five-second timeout. Accepted clears when that session starts running again or on the next write to it. For a write accepted while already busy, an unchanged running snapshot is not a new running transition. Rejected and Delivery unknown stay until explicit dismissal or target invalidation. Keep at most one receipt per exact live target, in memory only. Unknown delivery is never retried. Accepted never means task done or handoff approved. No auto-jump; ] moves on.

D7 Keep today’s working-session cards

Approved A. Keep variant A. Activity-led one-line rows are outside this epic. Calm technology favors scanning without inventing activity.

No activity-led one-line rows in this epic. Do not generate activity from chat text or pane tails. Only the selected visible runtime indicator may animate. Suppress stale activity on stopped or completed-current-step sessions without changing workflow position or runtime state.

D8 The same card at 60 and 30 columns

Approved A. At 60 keep the inline shell. At 30 the selected card fills the viewport while answering or replying. Norman needs clear focus; Tufte spends cells on the decision.

Expanded answer/reply content scrolls, never truncates. At 30, let the selected card use the viewport while editing, without a second renderer. Reserve identity and action rows before body rows. Page Up/Down scrolls the focused body; ←/→ switches questions outside literal text input. If height cannot fit identity plus action, show Open in Pi. This replaces the current 40-column answer minimum. Keep disclosure/state slots and reserve the worktree marker before fitting the title.

D9 Retire each replaced path

Approved A. Each owning ticket removes its old path. Norman favors one answer path; Tufte removes repeated controls. The epic still ships as one PR.

No parallel legacy UI after replacement. Rename footer Workspace to Details on i, and Open to Open in Pi. Enter / double-click opens Pi, i shows details/evidence, y copies the evidence path, and o explicitly enables follow view. Replace the existing p catalog action, not a second send command. Help, palette, footer, mouse and direct keys must use the same exact guarded target. Conversation retains completed typed messages and validated question/answer history, never live answer controls.

D10 Teach one repeatable loop

Approved A. Keep Next request visible and show one bounded dismissable cue. Norman makes keys discoverable; Horvitz leaves the pace to the user.

Use stable footer order ] Next request, p Reply, : All actions, ? Help. At 30 columns use ] Next, p Reply, : Actions. Focused answer/reply controls show their local keys instead. Keep numbers for pins outside answer focus and t for Theme outside custom text/answer focus. Help and : stay catalog-driven. Session search only selects/reveals; it never sends, answers, acknowledges or opens. Do not auto-advance after Accepted.

One semantic key

text #cdd6f4muted #a6adc8accent #89b4fasuccess #a6e3a1warning #f9e2aferror #f38ba8

Terminal base is Mocha #1e1e2e and selected background is #313244. Title is bold primary text; group, repo, task and description are muted. The exact selected marker uses accent. Semantic roles come from theme.ts/layout.ts. They do not change the current built-in theme.

Glyphs come from src/tui/glyphs.ts, including ▶ for the rpiv-style numbered option pointer. Do not import rpiv’s private view. Its inspected wrapping-select, tab-bar and dialog-copy implementations supply visual/wording references only; Hub retains its own input keys and no extra review modal.

Source boundaries

  • src/core/types.ts and session-context.ts own context and runtime fields. src/core/session-interaction.ts owns exact targets and pending question shapes.
  • src/core/conversation.ts reads typed tool calls from the supplied live branch. Preview enrichment must use the exact pending call identity on that source, not search conversation text or session files.
  • src/tui/render-model.ts, layout.ts, glyphs.ts and theme.ts own projection and geometry. dashboard-commands.ts owns commands; question-dialog.ts and form/text-input primitives supply focus/input patterns.
  • test/fleet-cards.test.ts supplies baseline fixtures. docs/FEATURES.md, docs/STRUCTURE.md, the epic and the Phase 3 maintainer notes define behavior and approval.
