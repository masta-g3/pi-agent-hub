Usage for pi-agent-hub

Design proposal for usage-001: a quota strip in the dashboard header and a full-screen Usage view. Every screen below is drawn from data at its real column width.

Render as 


120 columns. Each account shows its tightest window. A countdown appears only when a window is at 25% or less. ~ marks a stale account; ⚠ marks one with an error. Session counts and "needs you" always win the space.




140 columns: every window fits.




80 columns: only the most constrained account, with a count of the others. Narrower still, the strip disappears.



Cost tab




160 columns. One bold figure, then value and label pairs. The line under the axis is the chart cursor's readout and the legend: ← → move it, and it starts on today. Share bars reuse each provider's chart pattern.




80 columns. The summary takes two lines; the provider, cache and $/M columns drop. Bars keep the provider pattern, so the provider is still readable.



Limits tab




The ┃ mark shows where the fill would end if usage were spread evenly over the window. Codex 1's weekly fill stops ten cells short of it, so the projected run-out time is in warning color.




80 columns. Absolute reset times and the word "left" drop first. The pace mark stays even when the pace text is gone.



Where the numbers come from


  Pi session logs              Provider quota endpoints

          └───────────────┬──────────────┘
                          ▼
  pi-accounts   (own repo, ticket usage-snapshot-001)
    indexes logs: backfill, then live updates
    polls quota windows; drops emails; labels accounts "Codex 1"
                          │  writes a temp file, then renames it
                          ▼
  <PI_AGENT_HUB_DIR>/usage/
    pi-accounts-limits.json      accounts, windows, resets
    pi-accounts-history.json     daily, hourly and project rollups
                          │  read on each dashboard refresh tick
                          ▼
  pi-agent-hub
    stats each file; re-parses only when mtime or size changes
    validates version 1, caps rows, merges files; keeps it in memory
          │                              │
          ▼                              ▼
  header quota strip              Usage view (u)


Hub never reads Pi conversations, credentials or quota endpoints. It never writes usage data to registry.json, heartbeats or ui-state.json. Every dollar figure comes from the snapshot; Hub has no price table.

Recommended changes, ranked


    

  1. Add an even-pace mark ┃ to Limits bars. Pace text reads room to spare, on pace or fast: runs out ≈ time. This replaces the unclear "12% ahead".
    2. 

  2. Add a chart cursor (← → or click) with a readout line that is also the legend. Terminal bars cannot show their values any other way.
    3. 

  3. Give each chart series its own pattern plus a neutral color: █ accent, ▓ text, ▒ muted, ░ Other. Success, warning and error stay reserved for quota status.
    4. 

  4. Stack whole cells with the largest provider at the bottom. Use one bar-width and gap rule and evenly spaced date labels. Drop eighth-block tops, because they cannot show two patterns in one cell.
    5. 

  5. In the summary, make only the cost total bold. Rename "billed" to "recorded". Put "not your bill" and the update age on one muted line.
    6. 

  6. Header: always label windows (5h, wk). Show a countdown only at 25% or less. Use full account labels. Bars are never full or empty unless the value is exactly 100% or 0%.
    7. 

  7. Breakdown: cost and share sit right after the name and are right-aligned. Share bars use the row's series pattern. Column headers appear at 100+ columns. The name column takes the extra width.
    8. 

  8. Limits: remove provider headings. The plan, reset credits and age go under the account label. Show the relative reset time first.
    9. 

  9. Tabs and periods have fixed widths. Selected = selectedBg + bold accent, or brackets in NO_COLOR. Hide period chips on Limits.
    10. 

  10. The footer follows the dashboard convention: accent keys, muted labels, tap targets. It fits 80 columns.
    11. 

  11. Number formats: dollars with cents in tables; tokens in k/M/B with one decimal; integer percentages; ≈ on every estimate.
    12. 

  12. Tokens tab: same layout. The streak and weekday heatmap live here.
    13.
