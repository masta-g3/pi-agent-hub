Product design review · proposed state

From state console to attention cockpit

Five before-and-after mockups show how Hub can become calmer, faster, and easier to trust while Pi remains the agent runtime and tmux remains the process substrate.

Core claim: the interface must answer “which managed session needs me?” before it explains everything the system knows.

visual proposal not an implementation plan Herdr patterns, Hub boundaries diff seam: − remove · ↻ reshape · + add

Borrow the behavior, not the architecture

Keep Hub small and Pi-native

Take from Herdr

  • Attention-first state and direct routing.
  • One adaptive hierarchy with progressive detail.
  • Self-describing modes and consistent UI primitives.

Do not take

  • PTY ownership or a new background server.
  • Screen detection, multi-agent support, or plugins.
  • A persistent workspace → tab → pane product model.
01

Attention-first dashboard

Stop hunting for the blocked session

The current dashboard shows many correct state axes. The proposed dashboard converts those facts into one action queue without merging their internal meanings.

−↻+
1

Explicit producer attention leads. Runtime errors keep a separate health tier and never imply “needs you.”

2

The question appears inline. Hub does not infer attention from error, liveness, workflow state, or child activity.

3

Tiers are presentation, not new state. Each row keeps its own glyph: a waiting parent stays ◐ even while its subagent runs.

Outcome
The user can leave the dashboard and trust notifications that trigger only from explicit producer attention.
02

One adaptive cockpit

One surface, not a matrix of views

Today, the same sessions can appear as groups, workflow lanes, compact rows, or junction cards. The proposed surface changes density with available space but never changes its vocabulary.

−↻+
1

Width reveals room for context. It never launches or pins a session automatically.

2

Producer workflow stage remains a scoped row token and filter. It stops being a separate universe.

Outcome
A user learns one dashboard. The same hierarchy remains recognizable in a narrow pane, a normal terminal, and a wide monitor.
03

Intent-based commands

Replace the key maze with one discoverable action surface

Keep the fastest daily keys. Move infrequent and selection-specific actions into one searchable palette that teaches the same shortcuts as it exposes.

−↻+
1

The footer returns to six stable daily controls. It no longer acts as a compressed manual.

2

Every palette action still shows its shortcut. Discovery teaches muscle memory instead of replacing it.

Outcome
A user who knows six keys can perform every action. Help and footer derive from the active keymap, so they cannot drift.
04

Direct action workspace

Act on the session instead of operating its metadata

The right pane should explain what happened, show what is needed, and offer the next action. Live tmux panes remain the mechanism, but the numbered quadrant language disappears.

−↻+
1

Paths and implementation metadata move behind an Info action. The decision and consequence lead.

2

Pin creates a live tmux pane. Click focuses and tmux drag resizes. Hub does not become the runtime.

Outcome
Responding to an explicit request takes one action. Pinning a second live session also takes one action.
05

UX quality system

Make state explainable and every surface consistent

Quality must come from shared rules: semantic components, generated help, useful narrow layouts, status explanations, accessible symbols, and task-based visual validation.

−↻+
1

pi-hub explain and the Info pane show the reducer evidence in plain language.

2

Shared primitives govern modal spacing, action labels, focus, status symbols, narrow behavior, and visual fixtures.

Outcome
A new feature cannot invent a new interaction grammar. A confusing row can be diagnosed without reading source code.

Honest cost

The proposal removes concepts, not only pixels

Ordering changes

Attention-first presentation would supersede groups-first ordering in the primary view. Groups remain labels and filters.

View modes retire

The adaptive cockpit would retire density and workflow-board mode switches while preserving producer workflow data.

Panel grammar shrinks

Direct pinning would replace numbered quadrants. Existing shortcuts may move, so the final bindings need terminal-safe validation.

Decision frame

Choose the product direction before choosing tickets

Prototype the cockpit

Create static render fixtures for the attention queue, action workspace, and palette. Test common tasks before changing product contracts.

Adopt attention only

Keep current grouping and panels. Add strict attention semantics, notifications, and inline blockers first.

Keep the current model

Continue improving the existing groups, workflow board, density modes, and quadrant controls independently.

Proposed UI only. Pi remains the agent runtime. Tmux remains the durable process substrate. Herdr supplied reference patterns, not a target architecture.
