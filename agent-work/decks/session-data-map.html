The three producers

Intent, mechanism, and timing

All three paths are optional and independently validated.

1Rules runtime

Owner
rules/extensions/workflow-runtime
Intent
Show where the ticket sits in the tracked workflow.
Mechanism
No model and no prompt. Workflow skill, ticket, and Focus events append a Pi session entry. Hub copies it through the heartbeat.
When
State changes immediately. Hub heartbeats at agent start/end and every 15 seconds, then refreshes the dashboard in about 1 second.
Visible fields: workflow lane, step rail, ticket id, Focus mode.

2Parsed plan

Owner
Artifacts in the active repo; parsed by pi-session-summary.
Intent
Show the authored feature, checklist phase, progress, and next explicit task.
Mechanism
No model and no prompt. A deterministic parser reads agent-work/features.yaml and its linked Markdown plan, then writes the metadata JSON.
When
Turn start, every tool result, and before each semantic model call. Changed plan data reaches Hub on its next ~1-second refresh.
Visible fields: plan.feature, phase, task counts, phase counts, plan next step.

3Summary model

Owner
pi-session-summary
Intent
Explain the stable goal, latest verified progress, next action, and human handoff.
Mechanism
A model prompt receives bounded Pi activity facts plus compact ticket context. Output is sanitized and confidence-gated before the metadata file is written.
When
Turn start: 1.2 seconds. Activity: 2-second debounce and 5-second minimum model interval. Final output: 0.5 seconds. Calls time out after 2.5 seconds with no retry.
Visible fields: status, goal, semantic next step, attention, provenance age.

Not prominent in the dashboard

Hidden, support-only, or currently unmapped

“Not visible” does not always mean “not useful.”

Fields and inputs that do not become normal dashboard text.
Field or inputStateCurrent purpose or limitation
workflow.updatedAtsupportValidates producer state, selects the canonical workflow definition, and retains workflow position. It is not printed.
confidencegateBelow 0.5 removes semantic fields. Deterministic plan data survives. The score is not printed.
feature.descriptioninput onlyGrounds the model with the full tracked objective. It is not published as a dashboard field.
metadata.stagelow visibilityAppears only in expanded details and only when attention is absent. It never controls workflow lanes.
semantic nextStepmapping gapIt can appear in details when distinct from plan data. When no deterministic plan next step exists, current junction projection can suppress it as if the card rendered it, but the card does not.
Pi session nameseparate pathNot stored in metadata JSON. Session Summary can set the Pi name; Hub uses its stored title until the user runs name sync.
raw activity + full checklistnot publishedBounded activity stays model-input-only. The full checklist stays in Session Summary's local todo drawer.
Consolidation lens

The strongest overlap is ticket selection and “next action” naming. Workflow position, deterministic plan state, semantic progress, and Hub liveness remain different concepts.
