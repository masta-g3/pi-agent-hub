# Attention-first cockpit epic

Goal: Make Hub answer which agent needs the maintainer before exposing system state, then route the maintainer to the correct action.
Design reference: `agent-work/decks/cockpit-design-lab.html`; the approved choices in Layers 01–09 are authoritative.
Scope: Attention hierarchy and delivery, evidence, shared commands, decision workspace, named live panes, adaptive cockpit and workflow board, and onboarding.
Boundaries: Keep Pi as runtime, tmux as durable substrate, groups as labels, workflow metadata producer-owned and read-only, and attention explicit.
Implementation rule: Replace obsolete density, numbered-panel, details, and key-maze paths instead of adding parallel systems.
Excludes: Agent orchestration, runtime ownership, broad Git management, cloud/team features, inferred attention, raw pane-tail context, and notification history.

- `cockpit-001` — Done when the live project view projects independent attention, health, activity, quiet, and lifecycle tiers.
- `cockpit-002` — Superseded by `cockpit-001`.
- `cockpit-003` — Done when every derived runtime and placement decision has live evidence.
- `cockpit-005` — Works when one shared command model and `:` palette find sessions, valid actions, bounded context, and filters.
- `cockpit-006` — Works when the selected-session workspace leads with the decision, recommendation, contextual actions, and bounded producer context.
- `cockpit-007` — Works when named transient panes replace numbered slots with safe spatial control, a compact decision strip, and refusal without eviction.
- `cockpit-008` — Works when approved cards, trees, widths, and the retained read-only `S` workflow board replace obsolete density modes.
- `cockpit-004` — Works when fresh request identities announce once, acknowledgement silences delivery only, and non-attention changes stay silent.
- `cockpit-009` — Works when real-tier guidance retires after the first open-and-return loop and release guidance stays below attention.
