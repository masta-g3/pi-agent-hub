# pi-agent-hub Agent Notes

## Product Boundaries

- Keep Hub Pi-native and small: Pi is the agent runtime, tmux is the durable process substrate, and Agent Deck architecture stays out unless explicitly requested.
- Groups and lifecycle buckets are dashboard labels, not first-class records/projects. Custom dashboard shortcuts stay config-driven Pi text sends, not shell commands, macros, or event systems.

## Names and State Paths

- `pi-hub` is the primary CLI; `pi-agent-hub` remains a compatibility alias. Keep package/runtime/tmux state names as `pi-agent-hub` unless a full rename is requested.
- Keep global state under `PI_AGENT_HUB_DIR` or `<PI_CODING_AGENT_DIR>/pi-agent-hub`; never use `<PI_CODING_AGENT_DIR>/sessions`, which belongs to Pi conversations.
- Multi-repo workspaces live under `<PI_AGENT_HUB_DIR>/workspaces/<session-id>` and contain symlinks only. Repo picker history is one bounded `<PI_AGENT_HUB_DIR>/repo-history.json` file with no filesystem scanning.
- Hub-owned worktrees live under `<PI_AGENT_HUB_DIR>/worktrees`; support only explicit create/finish/discard flows, including one branch name across multi-repo sessions, unless broader Git management is requested.

## Dashboard Behavior

- Groups are implicit session labels: `g` moves the selected session, `G` renames its current group globally, and no empty-group lifecycle should be added unless the model changes.
- Active/Backlog/Archived are optional per-session buckets: `A` opens the Archive chooser (Done, Abandoned, or archive only), `B` moves to Backlog, and `U` restores and is the only Reopen for explicit closure. None stop tmux/Pi; subagent rows follow their parent. Keep closure independent of workflow completion and runtime; see `docs/STRUCTURE.md` for closure boundaries.
- Active/Backlog source rows use `src/core/session-order.ts`: across all groups, errors come first, then unacknowledged `waiting` rows newest-first, then every other row by last interaction, newest-first, regardless of runtime status. The user's own open, pin focus, answer, and send stamp that interaction through `touchSession`; rows without activity follow. Persisted user order breaks exact priority/activity ties, and `K`/`J` reorder only inside such a tie. Archived is globally newest-first by archive time and cannot be reordered. Do not sort by title or add a separate stopped section.
- The default Status fleet is a presentation-only stable partition of full owner trees: `NEEDS YOU` requires valid explicit producer attention on a waiting/idle owner; `HEALTH` requires owner runtime error; `NEW` requires an Active-lifecycle parent whose persisted `unopened` flag (set on create/fork, cleared only by the user's own `touchSession`, never by heartbeats) is still set, and stays expanded with no ` new` row badge under its heading; `ACTIVE` requires a starting/running owner or descendant; `QUIET` contains other non-archived trees; `ARCHIVED` remains lifecycle-owned and chronological. Classify from the full unfiltered fleet, then filter visibility. Descendants inherit owner placement, but child attention/error never promotes the owner and placement never changes row status, workflow, lifecycle, or attention. Surface hidden explicit child requests only as presentation-owner/tier counts derived from full-fleet request IDs minus visible projection IDs. Show each parent session's chosen group once: below the bold title as a muted bracket badge for Active fleet cards, in the right-side tail for dense Active rows, and before the title as a muted bracket badge for single-line lifecycle and narrow board rows. At 100+ columns the board uses group subheadings instead of repeating card badges. Repo grouping is a separate presentation choice based on actual source-path identity, not a project record; see `docs/STRUCTURE.md` for identity, ordering and disclosure contracts.
- Emit runtime and cockpit-placement evidence from the existing reducers, keep it on transient runtime/render projections, and never persist or couple it to workflow state. Reveal that evidence inside the selected-session action workspace; do not add a parallel Info screen. See `docs/STRUCTURE.md` for observation, invalidation, CLI, and workspace contracts.
- Do not repurpose established shortcuts: `r` restart choices, `R` rename, `N` sync from Pi `/name`, plus hidden compatibility aliases `e` for rename and `Alt+N` for sync.
- Keep catalog-owned direct keys, `:` palette entries, dashboard Help, configured actions, workspace rows, and stable footer controls sourced from `src/tui/dashboard-commands.ts`. Help is a static grouped reference using base labels and primary keys, never selected-session availability; keep keys complete and right-aligned. All invocation paths must honor the same availability guard. Bind contextual command, mouse action, and dialog/picker submission to the exact session/project identity; palette session results only select and ephemerally reveal, never attach, restart, or acknowledge. See `docs/STRUCTURE.md` for search, ordering, precedence, and reveal contracts.

## TUI Rules

- For dashboard glyphs and `NO_COLOR`, follow the ownership and text-preservation contracts in `docs/STRUCTURE.md` and the Plain terminals section in `docs/CONFIG.md`.
- Keep rendering pure/testable and ANSI width-safe through theme/layout helpers; reserve width for row prefixes, badges, and a readable title before retaining right-side metadata. Keep `dim` decoration-only; follow the readable color roles in `docs/STRUCTURE.md`. Reserve complete mode labels before fitting top-right owner signals. Board parent tails retain hidden requests longest, then active descendants, workflow, and age; keep Backlog and Archived on their lifecycle-specific ladders. Use one adaptive hierarchy: full no-pin Active cards show title, group/repo/branch metadata, task, then request. Keep task and request separate; selected content scrolls instead of being elided. Drop branch, then repo as width shrinks; show the producer grid at 80+, a plain step below 80, task counts/age at 160+, and incomplete live activity at 100+. Unselected neighbors retain the height ladder: at 61+ collapse to one line before scrolling. Dense rows keep bold titles and worktree/new markers, then muted group · age and the grid; drop group, then age, then grid before losing a readable title. Pin rows retain their title/metadata pair. See `docs/STRUCTURE.md` for fitting. Shared column labels come from producer steps in each section header; compatible rows show positional markers, while other pipelines retain an explicit current-step label. Mode labels stay in row metadata so they cannot shift the columns. Unselected lifecycle rows stay single-line; subagents use micro rows. Single-line lifecycle and narrow board rows keep `[group]` before the title; board cards under a group subheading omit the badge. All parent title rows place the worktree marker after the title, before `new`, and reserve its width before fitting the title. Keep a fixed disclosure slot, blank without descendants, and one state slot: explicit attention replaces the runtime glyph for waiting/idle rows without changing either axis. Session titles are bold primary text; group and repo names are muted, not bold. Running/starting rows use static `●` unless selected; only the visible selected row animates. Fleet metadata holds the group and multi-repo count once. Keep lower-priority metadata width-dependent; badge fitting rules live in `docs/STRUCTURE.md`. Keep the actual repository, full branch and compact repository count in the action workspace. Project cockpit tier headers are synthetic targets: NEEDS YOU is always expanded; HEALTH, ACTIVE, QUIET, and ARCHIVED have independent persisted collapse state, while Archived also has separate older-cascade disclosure. All synthetic headers, including repo headers, must block stale session actions and evidence/workspace access. Share effective visibility and exact selection between keyboard and mouse paths. Keep dashboard footer command metadata in `src/tui/dashboard-commands.ts` and TUI styling in `src/tui/layout.ts`, distinct from managed-session tmux chrome in `src/core/tmux.ts`.
- Keep the workflow board a read-only projection over producer metadata: no mirrored stage list or board persistence. Canonical workflow trees stay in producer lanes; every other Active tree appears once in synthetic `OTHER ACTIVE`. Nest cards under top-level parent groups. Board lane headings use bold Active-tier tone with parent counts beside the label; group subheadings are indented and muted, with only nonzero `?N` attention counts. Reuse the fleet workflow grid on board title rows, aligned to the projection's canonical producer vocabulary in lane headers; other pipelines keep an explicit current-step label. Keep modes and ages before the grid so its columns stay fixed. Subagent trees start collapsed in the fleet and board, use ephemeral `←`/`→` selected-tree and `Shift+←`/`Shift+→` all-tree disclosure state, accept `Space` as a board selected-tree toggle, and auto-reveal filtered child context without mutating disclosure state. Preserve one keyboard/navigation target per visible card; map visible continuation rows to their owning session only for mouse hit testing so whole-card single/double clicks match the title row. At normal 100+ widths, apply rich-tree gutters only after windowing, reserve the warning gutter for `NEEDS YOU`, and never imply a false end or continuation. Paint every visible line in the selected owner tree while keeping `▌` and all actions on the exact selected session. Top-level parent `⚙︎N` counts only starting/running descendants and never promotes child state. Treat workflow position, Hub runtime status, explicit attention, and running-subagent count as independent axes; show attention only for waiting/idle rows and never infer it from liveness. Use mouse-only header tier chips in Status fleet grouping, not Repo, board, or pin mode; hide zero-count tiers, keep owner counts beside tier labels, and reclaim the navigator column for the list. Keep progress bars board-only. `v` changes fleet grouping; `S` visits the board and returns to the chosen fleet grouping. Keep responsive geometry, hit-map, adaptive hierarchy, navigator, progress, and windowing details in `docs/STRUCTURE.md`; do not add parallel projections or renderers.
- Keep one selected-session action surface: the no-pin fleet expands in place; only the board uses a 34-cell column at 120–159, 44 at 160+, or an exact-session full-width screen below 120. Fleet actions use whole-item-fitted `key Label` items in catalog policy order; `i` toggles Details inside the card at every width. Board/pin workspaces retain positive-only blocks and label-first actions with right-aligned keys; the primary label is bold with accent `▌`. Use the complete ticket subtitle, or description only without one, and bind each action item to one exact catalog target. The palette label is `All actions`. One panel slot and renderer serve fleet, both board surfaces, pins and follow strips. Reserve identity/local keys, scroll the body, grow focused strips while retaining a list row, and show Open in Pi when too short. Status messages must not replace local keys. Board/pin compaction retains identity, the primary action, closure when possible and requested evidence. On session rows, `Enter`/double-click open/switch/restart Pi directly. Never capture or search tmux pane tails or search Pi conversation content. `c` toggles read-only Conversation below the fleet: typed completed messages and validated question/answer history from the selected live parent through the Hub extension. Keep conversation and preview text out of heartbeat, registry, and UI persistence. `p` opens Reply; Esc keeps drafts exact-target, Ctrl+U clears, Enter sends. `Tab` opens Answer; numbers select/toggle, `t` edits, Enter advances/sends. Esc never declines; choices stay request-bound. Preserve global keys outside answer focus and literal text inside input. Answers use official rpiv 2.15+ events in `docs/STRUCTURE.md`; configured commands use the same guarded bridge on every catalog path, never simulated keystrokes.
- Dashboard panes of 60 columns or less are frameless and render down to 30 columns; take every row, column, and hit-map offset from the layout shell inset, never a hardcoded frame. Footer items are tap targets that send their key through `SessionsView.handleInput()`.
- Route dialogs through `SessionDialog` in `src/tui/dialog.ts` and the small `src/tui/*-dialog.ts` modules. Use `src/tui/text-input.ts` for text editing and `src/tui/form.ts`/`renderForm()` for editable dialogs. Keep modal control rows at fixed screen coordinates as focus moves; reserve a stable help/error area instead of inserting focused hints between rows. Make text inputs, pickers, toggles, and submit actions visually distinct before focus. Dialog renderers report mouse hits through `src/tui/dialog-mouse.ts`; see `docs/STRUCTURE.md`.
- For themed footers, prefer Pi `statusLineBg` before `border` so Catppuccin border/accent colors do not become unreadable full-bar backgrounds.

## Persistence, Skills, and MCP

- Use `src/core/atomic-json.ts` for JSON state: `loadStore`, `updateStore`, `writeJsonAtomic`, and `isErrno`; avoid local errno helpers and parallel per-item read-modify-write loops.
- For Skills/MCP project state, write the final selection once. Pickers target the selected session's primary `cwd`, or dashboard cwd when nothing is selected; multi-repo sessions attach Skills/MCP only to the primary repo.
- Skill pool path editing lives in the `s` picker on `Alt+E`; `←`/`→` switch columns, `Tab` remains an alias, and printable keys including `e` must remain available for picker search.

## Tmux and Extension Behavior

- Clipboard is optional best-effort; attach/switch flows must always display the exact tmux command.
- Keep inside-tmux attach tmux-native with `src/core/tmux.ts`; do not stop/restart the TUI or add PTY attach unless outside-tmux return semantics are explicitly requested.
- Root `bind-key -n` shortcuts are server-global; preserve the passthrough and restore rules in `docs/STRUCTURE.md`. Numeric/spatial focus bindings send an intent to the exact saved sidebar pane; shell code must never resolve or focus a destination slot directly.
- Sidebar pins are nested tmux attaches identified by transient slot plus exact tty-to-managed-session identity. Never retarget, swap, replace, acknowledge on creation, or evict; the only exception is follow view (`o`, opt-in through `dashboard.followDefault`, reopening after archive/stop/delete until `o` leaves it), a single slot-1 pane marked by the transient dashboard-window option `@pi_hub_follow` that retargets to the exact live selection after it settles, never acknowledges or touches on retarget, and never coexists with pins; contraction preserves pins and blocks additions/resizing but must still permit safe close/rollback. Below 100 window columns (phones share the window), hide existing pins behind a Hub-made dashboard zoom instead of squeezing them; undo only Hub's own zoom and rebuild from the last wide geometry. Serialize inspection, reconciliation, mutation, focus, handoff, and shutdown through the side-pane queue. Keep topology, geometry, chrome, and recovery behavior aligned with `docs/STRUCTURE.md`.
- Preserve `dashboardEnv()` for any tmux return path that can recreate the dashboard so custom `PI_*` dirs survive.
- Export `PI_AGENT_HUB_PRIMARY_CWD=ManagedSession.cwd` on every managed parent launch, including direct conversation forks. Never export the multi-repo workspace cwd or an additional repo through this contract, and do not change normal `f` or worktree behavior.
- `Alt+R` rename-from-session intentionally round-trips through the dashboard action handoff and explicit rename dialog; do not add a parallel in-session rename UI to hide the flash.
- Tmux chrome must override both `*-style` and `*-format` options. Themes can embed ANSI/style directives in formats, not just styles.
- The extension can load via both `pi install` and managed-session `--extension`; keep registration idempotent and clear active guards on `session_shutdown`.
- `session.prelude` belongs in global `config.json` and runs only before managed `pi`; do not hardcode macOS keychain/SSH/direnv behavior or run it for dashboard/direct TUI.

## Lifecycle Safety

- Delete sessions through `src/app/delete-session.ts`, pause any active refresh loop first, and never delete Pi conversation/session files.
- Normal delete must not remove hub-owned worktree directories; finish/discard through `src/app/worktree-session.ts`.
- For worktree finish/discard, preflight Git cleanliness before stopping parent/subagent tmux sessions, process additional repos before the primary repo, and keep workspace `.pi` pointed at the source repo.
- Archive pruning is dashboard-only and starts after seven days: prune only after every row in the parent/subagent cascade is confirmed missing from tmux; keep rows when tmux presence is unknown.

## Compatibility Metadata

- Optional `kind: "subagent"` registry rows are owned by `pi-tmux-subagents`: keep them nested and short, show bounded task text in fleet micro rows, retain it in the action workspace/filtering, and disable normal session lifecycle/group/order actions on them.
- Optional producer-neutral `pi-agent-hub-context` Pi entries carry bounded ticket context, producer-accepted attention, and independently validated optional worktree lifecycle snapshots through the Hub heartbeat. Worktree snapshots never grant Hub ownership; Hub-owned active state comes from canonical mappings, while only partial/terminal evidence is retained. Structurally validate the latest versioned snapshot, ignore unknown fields, and never persist context into `registry.json` or couple it to Rules. Display attention only for waiting/idle rows; do not infer or reclassify it from confidence, stage, liveness, or workflow state. Fresh delivery requires a producer request ID; never infer an ID or persist delivery history.
- Keep producer-owned `workflow-runtime` separate from generic context: its workflow vocabulary, activity, deterministic plan, ticket identity, modes, and optional current-position completion remain producer-defined. Render completion positionally: earlier steps and a completed current step are checked, the incomplete current step is active, and later steps are pending. This is a position cue, not an execution audit; direct later-step invocation checks earlier positions without Hub sequence enforcement. Context, workflow position, completion, Hub liveness, native Pi naming, and attention are independent axes.

## Validation

- Do not run `npm test` and `npm run package:check` concurrently because both rebuild `dist`.
- If the user is actively using an installed/linked `pi-hub`, avoid build/package commands unless approved; prefer `npm run typecheck` for non-disruptive validation. Confirm install scope before building a dirty checkout: unrelated pending edits must not replace shipped behavior. Use the feature-only staging workflow in `docs/DEVELOPMENT.md` when only the reviewed feature is approved.
